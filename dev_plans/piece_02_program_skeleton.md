# Piece 2: the program skeleton

This piece turns the two libraries from piece 1 into a program that starts, checks its configuration, prepares its database, and answers a health check. It builds:

1. **`internal/config`**: reads and validates every environment variable once.
2. **`internal/store`**: the PostgreSQL connection, the embedded schema, the migrator, and the token table.
3. **`internal/auth`**: token generation, hashing, and reading a token from an HTTP request.
4. **`internal/httpapi`**: the HTTP handler. Only `GET /healthz` in this piece.
5. **`cmd/littlekittyvcs`**: the binary with two subcommands, `serve` and `admin-token`.
6. **`Dockerfile`** and **`deploy/compose/`**: the container image and a Compose file to run it beside PostgreSQL.

Done means: a bad master key refuses to start, and a good one serves `/healthz` with PostgreSQL up and the bucket unreachable. That is step 1 of the build order in [git_s3_server_plan.md](git_s3_server_plan.md).

The overall design is in that file. Its "Auth", "SQL migrator", "PostgreSQL", and "Configuration" sections were updated on 3 Nov 2026 for this piece: Basic-auth tokens for stock git clients, the `admin-token` subcommand, `idx_bytes`, and the token `label`. Where this document and that one disagree, report it. Do not silently pick one.

## Out of scope for this piece

No Git routes, no admin HTTP routes, no repository rows written, no pack upload or download, no `gc`, no snapshot import. The bucket client is constructed but never called. Do not create files in `internal/gitproto`, `objindex`, `packstore`, `push`, `fetch`, `snapshot`, or `gc`.

## Rules for whoever implements this

- **Leave every change unstaged.** No `git add`, `git stash`, `git checkout`, `git reset`, `git restore`, `git clean`, no commits.
- **No recursive or forced deletes** (`rm -rf`, `rm -r`, `rm -f`, `find -delete`), never a variable in a delete path. Tests clean up files only through `t.TempDir()`. The PostgreSQL tests drop only the schema each test created, by its exact generated name (see the store tests).
- **No backward compatibility.** Nothing has shipped. One migration file, `0001_init.sql`. No code reads an older shape.
- **No settings beyond the table below.** The only other environment variables are the test-only `LKV_TEST_*` ones, read only from `_test.go` files.
- **Never print a secret.** `MASTER_KEY`, `S3_SECRET_KEY`, `S3_ACCESS_KEY`, `DATABASE_URL` (it holds a password), and token plaintext never appear in a log line or an error message. The one exception is `admin-token` printing the new token to stdout, once.
- **Check every pgx name used below against the pinned module source.** The names here are from memory of the v5 API. If one differs, use the real one and list the difference in the report.
- **Do not touch** `internal/objcrypt` or `internal/blob` except to call them.

### API

```go
type Database struct {
    URL string
}

type Serve struct {
    Database
    MasterKey          [32]byte
    S3                 blob.S3Config
    Port               int
    PublicURL          string
    AnonymousRead      bool
    DenyNonFastForward bool
    AutoCreate         bool
}

// Getenv is os.Getenv in production and a map lookup in tests.
type Getenv func(string) string

func LoadDatabase(getenv Getenv) (Database, error) // admin-token: only DATABASE_URL
func LoadServe(getenv Getenv) (Serve, error)        // serve: every row of the table
```

- Collect **every** problem, then return one error that lists each variable name with a short reason, sorted by name, for example `config: MASTER_KEY: must be base64 of exactly 32 bytes; S3_BUCKET: required`. An operator fixing a fresh deployment sees all of it at once.
- The error names variables. It never contains a value. Test this (below).
- Do not wrap the error from `pgxpool.ParseConfig`. pgx quotes the connection string in its parse errors, with only the password masked, so the host, user, and database name would leak into logs. Report a fixed reason instead: `DATABASE_URL: not a valid PostgreSQL connection string`.
- `Serve` has no `String` or `Format` method, and no field is logged as a whole struct. The startup log line names only `Port`, `PublicURL`, the three booleans, `S3.Endpoint`, `S3.Region`, `S3.Bucket`, and `S3.PathStyle`.

## `internal/store`

### `store.go`

```go
type Store struct { /* *pgxpool.Pool */ }

func Open(ctx context.Context, databaseURL string) (*Store, error)
func (s *Store) Close()
func (s *Store) Ping(ctx context.Context) error

// NewID returns a random version 4 UUID as 16 bytes, from crypto/rand.
// Set the version nibble (byte 6 high nibble = 4) and the variant bits (byte 8 top bits = 10).
func NewID() ([16]byte, error)

var ErrNotFound = errors.New("store: not found")
```

- `Open` parses the URL with `pgxpool.ParseConfig`, creates the pool, and **pings with retry**: try every 2 seconds for up to 30 seconds, then return the last error. A database that comes up a few seconds after the app (normal in Compose and on App Platform) is not a crash. The error says the database was unreachable. It does not echo the URL.
- Scan UUID columns into `[16]byte`. Confirm that pgx v5 scans `uuid` into `[16]byte` directly in the pinned version. If it does not, use its `pgtype.UUID` at the boundary and keep `[16]byte` in this package's API.

### `migrations/0001_init.sql`

```sql
create table repositories (
    id          uuid primary key,
    name        text not null unique
                check (name ~ '^[a-z0-9][a-z0-9._-]{0,100}$' and name not like '%..%'),
    push_seq    bigint not null default 0,
    created_at  timestamptz not null default now()
);

create table refs (
    repo_id     uuid not null references repositories(id) on delete cascade,
    name        text not null,
    object_id   bytea,
    symbolic    text,
    primary key (repo_id, name),
    check ((object_id is null) <> (symbolic is null)),
    check (object_id is null or octet_length(object_id) = 20)
);

create table packs (
    id          uuid primary key,
    repo_id     uuid not null references repositories(id) on delete cascade,
    pack_key    text not null unique,
    idx_key     text not null unique,
    bytes       bigint not null check (bytes > 0),
    idx_bytes   bigint not null check (idx_bytes > 0),
    created_at  timestamptz not null default now()
);
create index packs_repo_created on packs (repo_id, created_at);

create table tokens (
    id          uuid primary key,
    token_hash  bytea not null unique check (octet_length(token_hash) = 32),
    label       text not null check (length(label) between 1 and 200),
    write       boolean not null,
    admin       boolean not null,
    repo_id     uuid references repositories(id) on delete cascade,
    created_at  timestamptz not null default now(),
    check (not admin or write),
    check (not (admin and repo_id is not null))
);
```

Notes for the implementer, not for the file:

- IDs are generated in Go (`NewID`), not by the database, because a pack's id names its bucket objects before its row exists.
- `object_id` is exactly 20 bytes: SHA-1 repositories only in version 1.
- `on delete cascade` is how deleting a repository removes its refs, packs rows, and tokens. The bucket objects are removed by the repository-delete route and `gc` in later pieces.
- An admin token always has write, and is never limited to one repository.

### `migrate.go`

```go
//go:embed migrations/*.sql
var migrationFS embed.FS

func (s *Store) Migrate(ctx context.Context) error
```

1. Read the embedded files. Each name must match `^(\d{4})_[a-z0-9_]+\.sql$`. The versions, parsed from the four digits, must be exactly `1..N` with no gap and no duplicate. Anything else is an error. This is a programming error, so it is fine that it only shows up at startup. A unit test catches it first (below).
2. `create table if not exists schema_migrations (version int primary key, applied_at timestamptz not null default now())`.
3. For each file in version order, in its own transaction:
   - `select pg_advisory_xact_lock(<constant>)`, using one fixed `int64` constant defined in this file with a comment saying what it locks.
   - If `schema_migrations` already has this version, commit and continue.
   - Otherwise execute the file's SQL, insert the version, and commit.
4. After the loop, if `schema_migrations` holds a version greater than `N`, return an error: the database is newer than this binary. Do not start on it.
5. Log each applied version at info level, and nothing when nothing was applied.

The lock makes several instances starting at once safe. The second instance waits on the lock, then sees the version already recorded.

## `internal/auth`

```go
const Prefix = "lkv_"

// Generate returns a new token: Prefix + base64.RawURLEncoding of 32 bytes from crypto/rand,
// and its SHA-256 hash. The plaintext is shown once and never stored.
func Generate() (plaintext string, hash [32]byte, err error)

// Hash is SHA-256 of the exact token string.
func Hash(token string) [32]byte

// FromRequest extracts a token from the Authorization header:
//   "Bearer <token>"            -> token
//   "Basic base64(user:token)"  -> token (the password); the username is ignored
// The scheme name is case-insensitive. A missing header, an unknown scheme,
// malformed base64, no colon, or an empty token returns ok=false.
func FromRequest(r *http.Request) (token string, ok bool)

// Challenge is the WWW-Authenticate value every 401 must carry, so git prompts for credentials.
const Challenge = `Basic realm="littlekittyvcs"`

type Token struct {
    ID     [16]byte
    Write  bool
    Admin  bool
    RepoID *[16]byte
}

// Allows reports whether the token may read (write=false) or write (write=true) repoID.
// A token limited to another repository is refused. A read-only token is refused for write.
func (t Token) Allows(repoID [16]byte, write bool) bool
```

`auth` does not import `store`. The HTTP layer in a later piece looks up `Hash(token)` through `store.TokenByHash` and converts the row to `auth.Token`. `FromRequest` does not check the `Prefix`. Hashing an unknown string just finds no row.

## `internal/httpapi`

```go
func New(log *slog.Logger) http.Handler
```

- A `http.ServeMux` with the Go 1.22 pattern `GET /healthz` (which also serves `HEAD`). Every other path is the mux's 404.
- `/healthz` returns `200`, `Content-Type: text/plain; charset=utf-8`, body `ok\n`. It does not touch PostgreSQL, the bucket, or any repository. It answers as soon as the listener is up, and the listener only opens after migrations succeed (see `serve`). So "healthy" means "configured and migrated".
- A small access-log middleware logs method, path, status, and duration at info level. It never logs headers, so the `Authorization` header can never reach a log line.

## `cmd/littlekittyvcs`

### Dispatch (`main.go`)

```text
littlekittyvcs serve
littlekittyvcs admin-token --label <text>
```

No subcommand, or an unknown one, prints a short usage message to stderr and exits with code 2. Any error from a subcommand is printed to stderr as one line, `littlekittyvcs: <error>`, and exits with code 1. `main` is the only place that calls `os.Exit`.

Logging: `slog` with a JSON handler on stdout, level info.

### `run.go`

```go
func runServe(ctx context.Context, getenv config.Getenv, ln net.Listener, log *slog.Logger) error
func runAdminToken(ctx context.Context, getenv config.Getenv, args []string, stdout io.Writer, log *slog.Logger) error
```

`runServe`, in this order:

1. `config.LoadServe(getenv)`. On error, return it. **Nothing else has happened yet:** no database connection, no listener.
2. `objcrypt.NewKeyring(cfg.MasterKey)`.
3. `blob.NewS3(ctx, cfg.S3)`. This does not contact the bucket. Keep the value, which later pieces will use.
4. `store.Open`, then `Migrate`.
5. If `ln` is nil, listen on `0.0.0.0:<Port>`. The address is `0.0.0.0`, never `127.0.0.1`: App Platform sends traffic to the container's interface.
6. One info log line naming the non-secret settings (see config), then serve `httpapi.New(log)` with an `http.Server` that has `ReadHeaderTimeout: 10 * time.Second`. Do not set `ReadTimeout` or `WriteTimeout`: a push or a clone can legitimately take many minutes.
7. When `ctx` is cancelled, call `Shutdown` with a 30-second timeout, close the store, and return `nil`. `main` cancels `ctx` on `SIGINT` and `SIGTERM` (`signal.NotifyContext`). App Platform and Docker stop containers with `SIGTERM`.

`runAdminToken`:

1. Flags from `args` with a `flag.FlagSet` that returns errors instead of exiting: `--label` (required, 1 to 200 characters).
2. `config.LoadDatabase(getenv)`, `store.Open`, `Migrate`. It migrates because an operator may create the first token before the server has ever started.
3. `auth.Generate`, `store.NewID`, `InsertToken` with `Write: true, Admin: true, RepoID: nil`.
4. Print exactly one line to `stdout`: the plaintext token. Log (to the logger, not stdout) the token's id and label, never the token.

## Tests

Run `go vet ./...` and `go test ./... -count=1` from the repository root, once with `LKV_TEST_DATABASE_URL` set and once without. Every test below must pass. Tests that need PostgreSQL skip with a message when the variable is unset.

### `internal/config/config_test.go`

Use a map-backed `Getenv`.

1. **All valid.** Every variable set: every field parsed, defaults applied when optional ones are unset (`Port` 8080, `DenyNonFastForward` true, the rest false).
2. **Everything missing.** An empty environment for `LoadServe` names all seven required variables in one error, sorted.
3. **Bad values.** `MASTER_KEY` of 31 bytes; `PORT` of `0`, `65536`, and `abc`; `S3_PATH_STYLE=yes`; `S3_ENDPOINT=fra1.digitaloceanspaces.com` (no scheme); `PUBLIC_URL=ftp://x`. Each is named in the error.
4. **No secret in any error.** Set `MASTER_KEY`, `S3_SECRET_KEY`, `S3_ACCESS_KEY`, and `DATABASE_URL` to distinctive invalid or valid sentinel strings while another variable is invalid. Assert none of those sentinel strings appears in the error text.
5. **`LoadDatabase`** needs only `DATABASE_URL`. A missing `MASTER_KEY` does not matter to it.

### `internal/auth/auth_test.go`

1. `Generate`: starts with `lkv_`, total length `4 + 43`, two calls differ, the returned hash equals `Hash(plaintext)`.
2. `FromRequest`: `Bearer t`; `bearer t`; `Basic` of `anything:t`; `Basic` of `:t` (empty username) all return `t`. A missing header, `Basic` of `user:` (empty password), `Basic` with invalid base64, `Basic` with no colon, `Digest x`, and `Bearer ` with nothing after it all return `ok=false`.
3. `Allows`: the full matrix of {read-only, read-write} × {all repositories, this repository, another repository} × {read, write}.

### `internal/store/store_test.go`

Each test isolates itself: it creates a schema named `lkv_test_<16 random hex>`, opens the store with `search_path` set to that schema (pgx `RuntimeParams`, or `?search_path=` on the URL), and in `t.Cleanup` drops **that exact schema** with `drop schema <name> cascade`. Nothing else is dropped.

1. **Embedded files are well-formed.** Without a database: the names match the pattern and the versions run `1..N`. Also test the validator itself with a fake list that has a gap and one with a duplicate. Both must be rejected.
2. **Fresh migrate.** The four tables exist and `schema_migrations` holds `1`.
3. **Migrate twice.** The second run applies nothing and returns `nil`.
4. **Concurrent migrate.** Five goroutines, each with its own `Store` on the same schema, call `Migrate` at once. All return `nil`, and `schema_migrations` holds exactly one row for version 1.
5. **Database newer than binary.** Insert version `99` into `schema_migrations` by hand. `Migrate` returns an error.
6. **Constraints hold.** A `refs` row with both `object_id` and `symbolic` set is rejected. So are a row with neither, a 19-byte `object_id`, a token with `admin=true, write=false`, a token with `admin=true` and a `repo_id`, and a repository named `Bad`, `a..b`, or `-x`.
7. **Tokens.** `InsertToken` then `TokenByHash` returns the same row. An unknown hash returns `ErrNotFound`. Inserting a second token with the same hash fails.
8. **Cascade.** Insert a repository and a token limited to it. Delete the repository. The token row is gone.
9. **`NewID`.** 1000 ids are all distinct, every one has version nibble 4 and variant bits `10`.

### `internal/httpapi/httpapi_test.go`

With `httptest`: `GET /healthz` gives 200, `ok\n`, and the content type. `HEAD /healthz` gives 200. `POST /healthz` is not 200. `GET /nope` gives 404. Send a request with `Authorization: Bearer lkv_secret` through the handler with a logger writing to a buffer. Assert `lkv_secret` is not in the buffer.

### `cmd/littlekittyvcs/run_test.go`

1. **Bad master key refuses to start.** `runServe` with every variable valid except `MASTER_KEY` (31 bytes), and `DATABASE_URL` pointing at `127.0.0.1:1` (nothing listens there). It returns an error naming `MASTER_KEY` **immediately**. Assert it returns in under 1 second, which proves it never started the 30-second database retry. No database needed.
2. **Healthy with the bucket down** (needs PostgreSQL). Valid config, `DATABASE_URL` to the test schema, `S3_ENDPOINT=http://127.0.0.1:1` (nothing listens). Pass a listener from `net.Listen("tcp", "127.0.0.1:0")`. Poll `GET /healthz` on it for up to 10 seconds: it returns 200. Cancel the context: `runServe` returns `nil` within 30 seconds, and the listener is closed.
3. **`admin-token`** (needs PostgreSQL). `runAdminToken` with `--label ops`. Stdout is exactly one line starting with `lkv_` followed by a newline. `TokenByHash(Hash(line))` finds a row with `Admin` and `Write` true, `RepoID` nil, and label `ops`. Without `--label` it returns an error and prints nothing to stdout.
